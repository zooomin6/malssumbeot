## 3. 설계 원칙

**원칙 1 — 감지는 넓게, 응답은 좁게.**
패턴은 손대지 않는다(D-004 유지). 분기는 응답 단계에서 한다.

**원칙 2 — 확인 단계에도 안전망을 남긴다.**
"확인을 한 턴 넣으면 진짜 위기자에게 안내가 늦어진다"가 이 설계의 유일한 반론이다.
이 반론은 **확인 질문과 함께 연락처 한 줄을 같이 내보내면 해소된다.** 확인은 톤을
조절하는 장치이지, 정보를 보류하는 장치가 아니다. 이 한 줄은 생략 불가로 못 박는다.

**원칙 3 — 판정 불가는 전부 안전 쪽으로.**
B등급은 명시적 조건을 만족할 때만 성립한다. 조건이 애매하면 A등급이다. 기본값이
안전이어야 한다.

**원칙 4 — 자기 대상과 타인 대상을 구분한다.**
케이스 2와 3을 가르는 결정적 신호는 **분노의 방향**이다. 케이스 2는 "사는 게 의미없고"로
화살이 자기를 향한다. 케이스 3은 "상사", "죽여버릴 수도 없고"로 화살이 밖을 향한다.

## 4. 제안 프로토콜

### 등급 판정 (결정론적, CrisisFilter 단)

```
자살자해/학대 패턴 매칭
  ├─ 학대 카테고리 매칭            → A등급
  ├─ 제3자위기 카테고리 매칭        → 제3자 안내 (기존 유지)
  ├─ 자살자해 패턴 + 분노맥락 패턴 동시 출현 → B등급
  └─ 그 외 전부                    → A등급   ← 기본값
```

`분노맥락`은 신규 카테고리이며 **단독으로는 아무 효력이 없다.** 자살자해 패턴과 동시에
출현할 때만 등급을 낮추는 보조 지표로 쓴다. 이 설계라면 분노맥락 패턴에 오탐이 있어도
위기 미탐으로 이어지지 않는다.

### 상태 관리

신규 상태를 만들지 않는다. B등급 확인 응답은 **D-026의 1회성 sticky 턴에서 처리**한다.
즉 기존 `CrisisSessionStore`를 그대로 재활용하고, sticky 턴에 등급 정보만 함께 싣는다.

### 승격·해제 규칙 (B등급 다음 턴)

| 사용자 응답 | 처리 |
|---|---|
| 분노·농담 취지로 확인 | 위기 해제 → 분노를 다루는 상담으로 이어감 |
| 정말 힘들다는 취지 | **A등급 승격** |
| 회피하거나 판단 애매 | **A등급 승격** |
| 대답 없이 다른 화제 | A등급 안내를 짧게 한 번만 남기고 화제를 따라감 |

승격은 있고 강등은 없다. B → A는 가능하지만 A → B는 없다.

## 5. `crisis.txt` 개정안 (전문) — ⚠ 무효, 아래 5-A 참조

> **정정 (2026-07-27, 코드 추적 후):** 이 절의 전제가 틀렸다. **`crisis.txt`는 데드코드다.**
> `PromptRepository`가 `byIntent`에 `Intent.CRISIS → crisis.txt`를 등록하지만,
> `ChatOrchestrator.handle()`은 위기 판정 시 `crisisReply()`로 즉시 반환하고 `generate()`를
> 타지 않는다. 2차 방어선(`Intent.CRISIS`) 경로도 동일하다. 따라서
> `PromptAssembler.assemble(Intent.CRISIS, ...)`는 호출되지 않으며 `prompts.crisis()`는
> 참조가 없다. 아래 프롬프트를 아무리 고쳐도 런타임 동작은 바뀌지 않는다.
>
> **A/B 분기는 프롬프트가 아니라 `ChatOrchestrator.crisisText()`의 고정 문구 분기로
> 구현해야 한다 (5-A).** 아래 원문은 문구 초안으로서의 가치만 남기고 보존한다.

```
<priority>최우선 — 다른 모든 지침에 우선함</priority>

시스템이 위기 신호를 감지했습니다. 감지 등급(<crisis_level>)에 따라 응답합니다.
등급이 주어지지 않았거나 판단이 서지 않으면 A등급으로 처리합니다.

## A등급 — 자기 자신을 향한 위기 신호 / 학대 피해 / 판정 불가

1. 신앙적 답변 모드를 즉시 중단합니다.
2. 따뜻하게 공감하되, 혼자 견디지 않아도 된다는 메시지를 전합니다.
3. 지금 곁에 있거나 오늘 연락할 수 있는 사람이 있는지 한 번 묻습니다.
4. 전문 기관을 안내합니다:
   - 자살예방 상담전화 109 (24시간)
   - 정신건강 위기상담 1577-0199
5. "기도하면 괜찮아질 거예요"로 마무리하지 않습니다. 전문적 도움과 신앙은 함께 갈 수
   있음을 전합니다. "믿음이 부족해서 상담을 받는 게 아닙니다"라고 분명히 말해도 좋습니다.
6. 위로의 말씀 한 구절(시 34:18 등)을 곁들일 수 있으나, 말씀이 전문 도움을 대체한다는
   인상을 주지 않습니다. 구절 본문은 <bible_verses> 원문만 사용합니다.
7. 사용자가 교회·공동체에서 상처받았다고 말하면 그것을 사용자의 신앙 문제로 돌리지
   않습니다. 공동체가 제 역할을 못 한 것이라고 분명히 인정하고, "그래도 교회는 나가야
   한다"고 권하지 않습니다.
8. 안전 평가 질문(자살 계획·수단·시기 등)을 캐묻지 않습니다. 당신은 임상 평가자가 아닙니다.
9. 자살이 구원에 미치는 영향 같은 교리 논쟁으로 들어가지 않습니다.

## B등급 — 외부 대상 분노 맥락의 관용적 표현 의심

"죽겠다", "죽고싶다"가 상사·동료·상황에 대한 분노 표현으로 쓰였을 가능성이 높은
경우입니다. 위기 문구를 그대로 쏟지 않되, 안전망은 반드시 남깁니다.

1. 먼저 짧게 확인합니다. 취조하듯 묻지 말고 한 문장으로.
   예: "한 번만 확인할게요. 방금 그 말은 화가 나서 하신 표현일까요, 아니면 정말
   힘들어서 하신 말일까요?"
2. 확인 질문과 함께 안전 정보를 한 줄 덧붙입니다. **이 한 줄은 어떤 경우에도 생략하지
   않습니다.**
   예: "정말 힘든 쪽이면 편하게 말씀해 주세요. 자살예방 상담전화 109도 24시간 열려 있어요."
3. 이 턴에서는 조언·말씀·기도문을 제시하지 않습니다. 확인이 먼저입니다.

  이어갑니다. 분노 자체를 죄로 규정하지 않습니다(엡 4:26). "크리스천인데 이런 마음을
```

## 5-A. 실제 구현 지점 — 고정 문구를 늘린다 (모델 호출 없음)

현행 `ChatOrchestrator.crisisText(category)`는 이미 카테고리별로 4종을 분기하고 있다.
`CRISIS_DEFAULT_TEXT` / `CRISIS_THIRD_PARTY_TEXT` / `CRISIS_ABUSE_TEXT` /
`CRISIS_SELF_HARM_TEXT`. **B등급은 여기에 5번째 고정 문구를 더하는 것으로 끝난다.**

```
CRISIS_AMBIGUOUS_TEXT (신규)
  조건: 자살자해 패턴 + 분노맥락 패턴 동시 출현
  내용: 확인 질문 1개 + 안전 정보 한 줄 (생략 불가)
```

이 설계의 이점은 **모델을 부르지 않는다**는 것이다. 위기 경로의 결정론적 안전 보장
(D-017·현행 구조의 핵심 전제)을 그대로 유지하면서 친구 3의 이질감만 제거한다.

### 개인화 문제도 같은 방법으로 푼다

"친구 2의 교회 상처가 통째로 무시된다"는 지적은 옳다. 그러나 그 해법이 곧 모델 호출인
것은 아니다. **조건부 고정 문단**이라는 중간항이 있다.

```
CRISIS_SELF_HARM_TEXT
  + (공동체상처 패턴 매칭 시) CHURCH_HURT_BLOCK 문단 1개 추가
```

`CHURCH_HURT_BLOCK`도 사람이 쓴 고정 문구다. 매칭 여부만 결정론적으로 판정한다.
개인화의 반대말은 고정 문구가 아니라 **고정 문구가 하나뿐인 것**이다. 문구를 조합하면
모델 없이도 "내 이야기를 들었다"는 감각을 상당 부분 회복할 수 있다.

> 안 vs 사람다움은 이 지점에서 정면 트레이드오프가 아니다. 트레이드오프가 되는 건
> **자유 생성**을 허용할 때부터다.



> 패턴 추가·삭제는 위기 감지 기준 변경이므로 민규 검토 대상이다.

```
# 분노맥락 (B등급 판정 보조 — 단독으로는 위기가 아니다.
#           자살자해 패턴과 동시 출현할 때만 등급을 낮춘다)
분노맥락	상사|부장|과장|팀장|사장|점장|교수|선임|사수|거래처|고객
분노맥락	짜증|빡치|열받|개같|지랄|미치겠|어이없|꼴받
분노맥락	죽여버리|패버리|때려주고싶
```

## 7. 부수 발견 — 기존 패턴의 오탐 하나

```
학대	때(리|려|렸|린)
```

공백 제거 후 부분 매칭이므로 **"때려치우고싶다"가 학대로 분류된다.** 직장 스트레스
문맥에서 극히 흔한 표현이라 실사용 오탐률이 높을 것으로 보인다. 게다가 케이스 3과
같은 상황에서 자주 겹친다.

최소 수정안:

```diff
-학대	때(리|려|렸|린)
+학대	때(리|려|렸|린)(?![치])
```

부정형 룩어헤드 하나로 "때려치우다"만 제외한다. 다른 학대 표현("때렸어", "때린다")은
그대로 잡힌다. 이 역시 감지 기준 변경이므로 승인 대상이다.

## 10. 남는 리스크 (정직하게)

- **B등급 오판**: 분노 맥락으로 위장된 진짜 위기를 놓칠 수 있다. 원칙 2의 "안전 한 줄"이
  이 위험을 상당 부분 흡수하지만 0으로 만들지는 못한다.
- **분노맥락 패턴의 커버리지**: 목록에 없는 표현으로 화를 내면 A등급으로 떨어진다.
  이건 안전 방향의 실패라 수용 가능하다.
- **한 턴 지연**: B등급에서 A로 승격되는 경우 전체 안내가 한 턴 늦다. 다만 그 턴에도
  109는 이미 전달된 상태다.
- 이 문서의 제안은 임상 전문가 검토를 대체하지 않는다. PROGRESS.md "사람 확인 필요"의
  전문가 검토 항목과 함께 다뤄야 한다.

## 11. 구현 함정 4건 (2026-07-28 코드 대조로 확인 — 구현 전 반드시 읽을 것)

> 이 문서를 그대로 구현하면 아래 넷에 걸린다. 설계 방향은 유효하나 구현 세부는 정정이 필요하다.

### 🔴 함정 1 — 보조 패턴을 `crisis-patterns.txt`에 그대로 넣으면 "짜증나"가 위기가 된다

`CrisisDetector.detect()`는 카테고리를 구분하지 않고 **어떤 패턴이든 매치되면 즉시 신호를 반환**하고,
`CrisisFilter.check()`는 신호가 있으면 무조건 `crisis()==true`로 만든다. §6의 분노맥락 행을
같은 파일에 추가하면:

```
"아 짜증나" → 분노맥락 매치 → 위기 발동
            → crisisText("분노맥락")이 어느 분기에도 안 걸림
            → CRISIS_DEFAULT_TEXT (109·1577-0199·112) 반환
```

§6 주석의 "단독으로는 위기가 아니다"는 **코드가 읽지 않는다.**
→ 보조 패턴은 **별도 파일**(`context-patterns.txt` 등)로 분리하거나, detector에
   "보조 카테고리 단독 발동 불가"를 코드로 강제한다.

### 🔴 함정 2 — 첫 매치에서 멈추므로 "동시 출현" 판정이 불가능하다

`detect()`는 `Optional<CrisisSignal>` **하나**만 반환한다. "자살자해 + 분노맥락 동시 출현"을
알 방법이 없다. 같은 이유로 `CHURCH_HURT_BLOCK`도 불가능하다 — 자살자해가 먼저 매치되면
공동체상처 패턴은 검사조차 되지 않는다.
→ 주 카테고리(첫 매치)는 유지하되 **보조 카테고리 집합을 함께 반환**하도록 변경.
   기존 테스트 108건을 깨지 않는 방향으로.

### 🟠 함정 3 — 공동체상처 패턴이 OR이면 거의 항상 붙는다

`교회|목사|성도|무시|소외`를 OR로 나열하면, **이 앱에서 "교회"는 거의 모든 대화에 나온다.**
교회 이야기를 긍정적으로 한 사용자에게도 "그건 교회가 잘못한 겁니다" 문단이 붙는다.
→ 분노맥락과 같은 **AND 구조**로: `(교회|목사|성도|공동체|예배)` AND `(무시|소외|상처|배척|외로|눈치)`

### 🟠 함정 4 — 학대 우선순위 누락 + `죽여버리`가 강등 트리거에 있음

5-A가 학대를 다루지 않는다. 학대를 A등급에 흡수하면 두 가지가 후퇴한다:
`CRISIS_ABUSE_TEXT`의 1366·1388·112가 사라지고, **"곁에 연락할 사람이 있는지" 질문이
되살아난다** — 곁의 사람이 가해자일 수 있어 의도적으로 제거했던 문장이다(코드 주석에 근거 있음).

또한 §6의 `분노맥락 죽여버리|패버리|때려주고싶`은 §공통("타인을 해치겠다는 의사는 A등급")과
**같은 단어가 강등 근거이자 승격 근거**가 되는 모순이다. 케이스 3의 "죽여버릴 수도 없고"가
수사인 이유는 `죽여버리`가 아니라 **"~수도 없고"라는 체념 어미** 때문이다.

→ 분기 순서를 명시한다: `학대 > 제3자 > (자살자해+분노맥락) > 자살자해 > 기본`
→ `죽여버리|패버리|때려주고싶`을 분노맥락에서 제외한다.
